# Per-job ceilings on the number of tests that may SKIP when a job runs.
#
# Format: <job key><TAB><max skipped tests><TAB># why
# Checked by scripts/check-skip-budget.sh. See that script for the reasoning.
#
# A budget is not a target. Where a job provisions a resource, the right number
# is 0: a skip then means something it set up did not arrive. Where a number is
# larger, it is because the job deliberately does not configure something --
# the engine job runs against PostgreSQL only, so its MySQL and SQL Server
# subtests are "nobody asked", which is the one thing a skip is allowed to mean.
#
# RULE OF THUMB, learned the expensive way four times in one afternoon: any new
# test gated on a dialect costs a skip in every job that does not configure that
# dialect. Two shapes to watch:
#
#   * a test running against registeredBackends costs TWO skips (its mysql and
#     mssql arms) in every PostgreSQL-only job -- test-go/engine AND cluster,
#     which move together;
#   * a test gated on CLEAT_TEST_MYSQL/CLEAT_TEST_MSSQL costs ONE in whichever
#     job runs its package without that dialect -- for ./migration/... that is
#     test-go/support.
#
# Work out which jobs run the package you touched, and bump those, before
# pushing.
# To check without waiting for CI:
#
#   env -u CLEAT_TEST_MYSQL -u CLEAT_TEST_MSSQL -u CLEAT_TEST_POSTGRES \
#     CLEAT_TEST_DB=postgres://... go test -count=1 -p 1 -json ./engine/... > r.json
#   scripts/check-skip-budget.sh test-go/engine r.json
#
# THE `-p 1` IS NOT OPTIONAL, and this command was missing it until 2026-08-09.
# `./engine/...` matches two database-backed packages -- engine and
# engine/testutil -- and without -p 1 Go runs them concurrently against one
# database. engine/testutil's CleanupPostgresTestData is an unqualified DELETE
# across eleven tables, so it wipes the other package's fixtures mid-test.
#
# Measured 2026-08-09 on develop, same machine, live PostgreSQL 16, eight runs
# each way:
#
#   without -p 1   3 of 8 runs failed
#   with    -p 1   0 of 8 runs failed
#
# The casualties are whichever package loses the race, which is the tell:
# usually TestAdminForceResolve_RefusesAnotherTenant and
# _AuditCollisionRollsBack in ./engine (an FK violation on a workflow_defs row
# the test itself had just deployed), but one run instead took out
# TestCleanupPostgresTestData in ./engine/testutil. Both pass in isolation.
#
# It looks exactly like a flaky product defect and is not one -- a session was
