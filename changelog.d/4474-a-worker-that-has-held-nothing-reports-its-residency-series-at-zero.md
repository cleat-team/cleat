- **`/metrics` on a worker that had held nothing left out the residency series, so "nothing held" and "the exporter is broken" looked alike (cleat#4474).** The exporter writes an instrument out only after its first measurement, and a worker with residency on recorded only the budget at start-up: `cleat_resident_runs`, `cleat_resident_memory_charged_bytes` and the four residency counters (`cleat_resident_parks_total`, `_refusals_total`, `_rechecks_total` and `_evictions_total`) were absent until something first moved them, and on a workload whose waits are all longer than the residency window the held-run series never appeared. A worker with residency on now records a 0 for both gauges and for every counter series the engine can emit, by the label values it records (a kind that cannot end a given way has no series for it). A worker with residency off still exports no residency series. `cleat_workflows_active` is unchanged: it is labelled by workflow name, so it appears when a run of that workflow first starts, and a missing series there means 0 (`sum(cleat_workflows_active) or vector(0)`; see "Reading the residency metrics" in `docs/reference/worker-config.md`). If an alert or a dashboard uses `absent()` or a series count on a residency series, read it again: a series that reads 0 now exists where there was none.
