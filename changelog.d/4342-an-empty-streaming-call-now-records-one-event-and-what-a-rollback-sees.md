- **An empty streaming call now records one event, so a run that makes one has an extra row in `event_history` and the events API (cleat#4342).** A `plugin_call_stream_chunk` row with an empty `output`, `stream_data` true, a non-zero `stream_err_code` and no `stream_finish`; it counts against `--max-quota-events` and moves the step numbers after it by one for a NEW run. **The SSE stream endpoint does not serve it** (it is not a chunk the plugin produced), on the history read and on the durable tail; a client reading the events API or the database directly sees the row. **Rolling back across this change:** a 0.5.x worker does not know the data flag and reads the row as an ordinary chunk, so **a run that made an empty streaming call under 0.6.0 may see a one-element stream instead of `null` at that call if it is replayed by 0.5.x**, and an empty stream followed by another stream of the same function replays on 0.5.x exactly as it did before this change (the next stream's chunks served to the empty call, and its function run again). Rolling back across a minor release is not a supported path; this is stated so that nobody finds it out from a workflow.
