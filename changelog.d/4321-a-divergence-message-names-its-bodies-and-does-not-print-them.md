section: upgrade
---
- **A replay divergence message no longer prints a request, a response or a payload; it gives each one's size and a short hash (cleat#4321).** The message is handed to the workflow and from there reaches the run's stored error, the logs and the API, and by replay time the engine holds the decrypted payload, so a run that encrypted its sensitive payloads still wrote them out in clear text in that sentence, and egress redaction could not reach text that only contains a document. The lines keep their labels (`actual request:`, `expected request:`, `actual body:`, `expected body:`, `actual input:`, `expected (cached) input:`, `expected (cached) output:`, and the `input=` of `schedule_cron`), and each value is now `[redacted: <n> bytes, sha256=<16 hex digits>]`. It covers the plain, retried and heartbeat calls, `fetch` (both the type divergence and "with a different body"), `schedule_cron` (both forms), plugin calls, and the `wait_for_event` message about an output that is not claim-shaped. Equal payloads show equal size and hash, so you can still see whether a payload changed; read what it held from the history (`GET /api/workflows/<id>/history`). Anything that parsed a body out of a divergence message must read the history instead. A run ID in a child await's message is an identifier and is still printed.
