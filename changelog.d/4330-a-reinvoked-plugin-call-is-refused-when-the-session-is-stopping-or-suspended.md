- **A replayed `plugin_call` whose function may be re-invoked on replay no longer runs the function live while the session is stopping, after it has suspended, or in a defer segment (cleat#4330, cleat#4285).** Every other way a plugin call arrives refused first, but the re-invocation path (cleat#1318: a registration, or a record, that carries both the idempotent and the same-value replay flags) had neither the stop refusal nor the suspension refusal, so a worker that was shutting down, or a guest that ignored a suspension, ran the function again and handed the guest its live answer. It is now refused like every other call, and answers the stop word with nothing run. **What was reachable:** `blobstore.blobGet` (a read) and `llm.embed` (a model call that costs money) are the two functions this repository registers with both flags, and any plugin whose manifest or options declare both qualifies. By policy those functions are idempotent and return the same value, so this was live work after a stop and not a duplicated side effect, unless a third-party plugin declared both flags wrongly. A structural test now reports any host call that reaches live work by a path that skips the refusal, and any step whose recorded-answer path runs live work.
