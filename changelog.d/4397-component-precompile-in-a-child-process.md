- **`--component-precompile` (EXPERIMENTAL, off by default): compile a Python or C# workflow in a short-lived child process, so the worker does not keep the compile's memory (cleat#4397).** The first Python compile adds about 490 MiB to a worker and most of it stays; loading the child's artifact instead leaves the worker at about 68 MiB (measured in a container, 2026-11-23). It lowers the steady state, **not the compile peak**: the child shares the worker's memory limit. At a 512 MiB limit, a stated tight configuration, the worker compiles its first Python workflow with about 60 MiB to spare (arithmetic, not a measured anon peak); with the flag off it is OOM-killed (3 of 3). `--component-precompile-parallel` (`auto`: parallel unless the memory limit is under 1 GiB) and `--component-precompile-timeout` tune it. A child that fails for an ordinary reason falls back to the in-process compile. A child that is SIGKILLed (the OOM killer) is **not** answered by compiling in the worker, which would kill it: the run is released with a back-off, not failed, no further child is started for that component for 5 minutes, and the worker logs an ERROR and counts `cleat_workflow_releases_total{check="component_compile_refused"}`. Where `memory.oom.group` is 1 (Kubernetes' default on cgroup v2, per its documentation, not measured here) an OOM kill takes the whole container, and the worker warns at start-up. See `docs/reference/worker-config.md`.
