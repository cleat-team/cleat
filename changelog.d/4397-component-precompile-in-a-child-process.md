- **`--component-precompile` (EXPERIMENTAL, off by default): compile a Python or C# workflow in a short-lived child process, so the worker does not keep the compile's memory.** The first Python compile adds about 490 MiB to a worker and most of it stays; loading the child's artifact instead leaves the worker at about 68 MiB (measured in a container, 2026-11-23). It lowers the steady state, **not the compile peak**: the child shares the worker's memory limit. At a 512 MiB limit the worker compiles its first Python workflow, with about 60 MiB to spare; with the flag off it is OOM-killed (3 of 3). `--component-precompile-parallel` (`auto`: parallel unless the memory limit is under 1 GiB) and `--component-precompile-timeout` tune it. A child that fails for any ordinary reason falls back to the in-process compile; a child that is SIGKILLed (the OOM killer) fails that execution with a message naming the memory limit instead, because compiling in the worker would kill it. See `docs/reference/worker-config.md`.
