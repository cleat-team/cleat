- **`create_promise`, `resolve_promise` and `reject_promise` whose promise-store write failed now replay as that failure (cleat#4335, cleat#4203).** The three calls recorded their event first and wrote the store second, so a write that failed (or a worker with no promise store) was reported to the guest as an error while the recorded history said success, and a replay of that history answered **success**. A workflow that branched on the error took one path on its original run and another after a replay. The calls now write the store first and record how it went: a failed write is recorded on the event, and the replay answers the same error, with the same message for `create_promise`, without writing the store again. The failure is part of the event's checksum and survives compaction. This also changes what a crash between the two steps leaves behind: it used to be an event whose row was never written (read from the code, not measured: the replay would answer success with an id nothing had created, and an await of it would wait for ever, the hang IMPROVEMENT-PLAN 3.218 describes for a missing row); it is now a row whose event was never recorded (the replay runs the call again, and for `create_promise` generates a new id, so the first row is an orphan that no guest was given). The known limitation this closes is removed from `docs/determinism.md`.
