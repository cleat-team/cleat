- **The compiled-component cache charges a Python or C# component for what it holds, and its default bound is 1 GiB (cleat#4389).** A component was costed at four times its wasm, which under-counted every one measured on 2026-11-23: Python by 1.35 to 1.5 times and C# by up to 2.2 times, because most of a component's wasm is a memory snapshot and not code, so its length does not predict the compiled cost. A component is now costed at 3.5 times its serialized compiled artifact, which tracked the live cost within 2.0 to 3.0 times across five components (a Python component counts 111 to 153 MB, a C# one 11 to 30 MB). At the old 512 MB default that charge would have held three distinct Python components, so `--wasm-module-cache-max-mb` now defaults to **1024**, which holds about six to seven, with the live cost near 100 MiB each (about 650 MiB for a full cache; measured in a 2 GiB container with the nine distinct Python components, `--component-precompile` (the default in 0.6.0) let the cache fill, 60 held-eligible runs and a further compile complete at a container peak of about 1.1 GiB, where compiling in the worker kept 198 to 308 MiB for each of the first four further distinct components and 44 to 76 for each of the next three (mean 175) and the container was killed on the ninth). A deployment that runs more distinct Python workflows than that will evict and recompile (about 1.5 s each) unless it raises the flag, and one that set the flag itself keeps its value, which now holds fewer components than it did; the reference page has the table and the sizing advice. Core-module workflows (Go, Rust, Java) are charged as before.
