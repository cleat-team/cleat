- **`plugin_call_streaming` now replays through the step dispatcher, and a replay whose records are not the call's own is a divergence (cleat#4152, G3).** The events it records (one `plugin_call_stream_chunk` per chunk, and one synthetic finished chunk for a stream-level failure), their order, the chunks published to a live reader, the answer a guest is handed on a healthy replay, the redaction of a failed call's recorded input, the error codes and the answer for a worker with no plugin stream registry are unchanged: a table of 39 situations, recorded from the code before the move (cleat#4339), reads byte-identically for 31 of them, and the eight that changed are listed here (this change adds six rows that read the same on the old code except one, below). **Replay used to check neither the plugin nor the function a record names**, so a record for another function or plugin was served as the call's answer; it is now a divergence (`plugin stream function p/f, recorded q/g`) that consumes nothing. **A record that is not a chunk at the call's step** used to answer SUCCESS with a `null` stream and not advance; it is a divergence now. **Two adjacent streams** used to be read as one (the first replay returned both calls' chunks and the second ran its function live again, recording and publishing its chunks a second time); each run now ends at its finished chunk, so each call is answered its own chunks. A tool that watched for a divergence message on this call had none before; there is one now. **Not changed, and still wrong:** a stream that produces no chunk records nothing, so two adjacent streams of the SAME function, the first empty, are still read as one by a replay (cleat#4342). A history that ends inside a stream that never finished is answered from the chunks it recorded, as before, and the session now leaves replay on that call; and a stopping or suspended session now refuses a streaming call at the replay frontier through the dispatcher's own refusal, as it refuses any call, **including one whose history ends inside a stream: it is answered the stop word and not the recorded chunks** (a ninth changed row).
