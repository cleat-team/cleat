- **A Python workflow instance costs about 1.3 MiB of memory instead of 12 MiB (cleat#4382).** wasmtime shares a module's initial memory between instances through a copy-on-write image, but only when the module's data covers at least half of its span (or the span is under 16 MiB). The CPython module covers 49% of 21.7 MiB, so it got no image and every instance copied its 10.6 MiB snapshot (a fit over 1 to 64 instances, measured 2026-11-22). `cleat build --target python` now merges the module's data segments into one, with the gaps zero-filled, so linear memory is byte-for-byte the same and the module gets an image; instantiating a Python workflow also drops from about 6 ms to 0.03 ms. The component is about 11.6 MB larger on disk (18.5 MB to 30.1 MB) and the compiled-module cache charges a component by its compiled size (cleat#4389: 3.5 times its serialized artifact, with a 1 GiB default bound), so a deployment that keeps many distinct large Python components cached may raise `--wasm-module-cache-max-mb`. Residency charges a held Python run 11 MiB against its memory budget, which is the cost after a guest has churned large allocations and not this idle figure (cleat#4377). Rebuild Python workflows to get it: a component built before this change keeps its old cost.
