---
section: upgrade
---
- **The record that tells a timed-out await from an answered one is written from this version on; a history recorded before it keeps the old answer (cleat#4277).** The shape that stays ambiguous is an `await_promise` event followed at the very next step by a `promise_resolved` or `promise_rejected` event of the same promise, with no `first_read` in the settlement. A replay of one still hands the await the resolution, as it always did, even when the original run had been told it timed out. **To find the runs where it could matter:** look for that pair where the settlement's `timestamp_ms` is later than the await's `timestamp_ms` plus its `timeout_ms`. A settlement recorded inside the await's own window is an answer to it and is never the other shape. The test is a superset: a wake that found the promise already settled after the await's deadline records the same pair and is not affected. Only awaits made after the upgrade are recorded with the marker. The marker is a new field of the settlement event, inside its checksum only when it is set, so no event written before this version changes its checksum. **A worker from before this change (0.5.x, or develop before it) that replays a history written after it fails with a checksum mismatch.** The marker is inside the settlement event's checksum, and every `await_promise` that finds its promise already settled records it, not only the timeout race, so ordinary runs are affected. The replay verifier is on by default (`VerifyWorkflowEvents`, wired in `cmd/cleat-worker/setup.go` with `failOnMismatch` true), and, measured on a real MySQL with the code from before this change, it refused `[await_promise, promise_resolved first_read]` written by the new code with `step 1: checksum mismatch`, where the same shape without the marker verified clean. So upgrade by stopping every worker and then starting the new version, as the rolling-upgrade known issue already says, and do not roll back to an older worker once the new one has run workflows that await promises: an older worker cannot replay what they recorded. Keeping the marker inside the checksum was a deliberate choice, since integrity coverage of the field matters more than tolerance of an older worker.
