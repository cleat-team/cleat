- **A streaming plugin call whose stream produced no chunk no longer makes a replay hand the NEXT stream's chunks to it and run that next call's function a second time (cleat#4342).** An empty stream recorded nothing, so a replay could not tell it from a call that was not there: `[empty A][stream B]` of the same function replayed B's chunks as A's answer, and B reached the replay frontier and **ran its plugin function live again**, recording and publishing its chunks a second time. The call now records a marker, an existing record shape and no new event type (a `plugin_call_stream_chunk` with the data flag and a non-zero error code, a combination no other writer produces, kept true by a source scan), and the guest is answered `null` as it always was. **A history recorded before this change cannot be repaired**: an empty stream in it recorded nothing, so two adjacent streams of the same function with the first empty are still read as one on replay. **One shape is still wrong and is pinned:** an UNFINISHED stream (one that never sent a finished chunk) directly followed by an empty stream of the same function.
