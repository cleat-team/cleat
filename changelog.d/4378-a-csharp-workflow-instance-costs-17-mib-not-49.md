- **A C# workflow instance costs about 17 MiB of memory instead of 49 MiB, which also lets residency hold about three times as many of them (cleat#4378).** A .NET guest on WASI started its GC with three 16 MiB heap segments, and the WASI reservation writes every byte it reserves, so an empty workflow occupied 48.7 MiB per instance (a fit over 1 to 64 instances, measured 2026-11-22). The C# SDK now sets the GC segment size to 8 MiB, which makes the same workflow cost 16.7 MiB; 4 MiB, the smallest the GC accepts, would cost 12.7. A workflow that holds many large objects pays about a quarter over its data for segment rounding, and an allocation-heavy one runs a few percent slower with somewhat more GC pause. Set `CleatGcSegmentSizeHex` in the project to change the size. Rebuild C# workflows with `cleat build --target csharp` to get it: a component built before this change keeps its old cost.
