- **A run held through a signal wait (`await_signals`) now resumes when its signal arrives, instead of being suspended and replayed (cleat#4162): within milliseconds on PostgreSQL (the worker's `--notify-channel` listener nudges held waits on each NOTIFY, at most one recheck per 50 ms per held run, since that channel carries every dispatch wake-up) and within one `--poll` interval on MySQL and SQL Server, which have no NOTIFY.** Residency is ON by default (`--resident-max-runs` is 8; 0 turns it off). A held signal wait asks the store whether its signal has arrived once straight after it is held and then every `--poll`, on PostgreSQL, MySQL and SQL Server alike. **At the defaults only short request/reply waits (a timeout up to about 10 s) are held; long approval waits are not, by design.** A signal that lands just before a held run is sent back is not lost: the release wakes the run at once. Each check is counted by the new `cleat_resident_rechecks_total{kind,result}`. Promises, children and updates are not held yet.
