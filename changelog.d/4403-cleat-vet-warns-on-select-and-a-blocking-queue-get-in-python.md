- **`cleat vet` warns about `select.select` and a blocking `queue.Queue.get` in a Python workflow (PY017, cleat#4403).** A workflow is single-threaded, so neither can do anything but wait, and neither was flagged. Measured on a worker (PostgreSQL, macOS arm64, `--concurrency 32`): `select.select([], [], [], t)` blocks in the host for the whole timeout, like `time.sleep`: a `--concurrency` slot and one OS thread for the duration, and `--wasm-instance-timeout` did not interrupt it (a 1 s call ran 1.11 to 1.16 s under a 250 ms timeout); `queue.Queue().get(timeout=t)` busy-loops in the guest (5.17 CPU-seconds over a 5 s wait) and the instance timeout does stop it. It is a warning and never an error, so it refuses no build that runs today; `get_nowait()` and `get(block=False)` are not reported. Names are resolved through the file's own imports; a queue that arrives as a parameter is not recognised. A blocked execution pins one OS thread, which the Go runtime keeps for the worker's lifetime: the count settles at the highest number of executions blocked at once and does not grow with the number of sleeps.
