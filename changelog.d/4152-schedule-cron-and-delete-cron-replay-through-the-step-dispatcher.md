- **`schedule_cron`, `delete_cron` and `list_crons` now replay through the step dispatcher, and a replay that meets the wrong record no longer consumes it (cleat#4152, G1c).** Three host calls moved onto the dispatcher the promise and lock calls use; their events, order, checksum chain, guest-visible results on a healthy replay, and suspension are unchanged, and a golden table recorded from the old code (`engine/a_cron_single_steps_behave_as_recorded_before_the_dispatcher_test.go`) shows every row but eight byte-identical. The eight that move are all replay divergences: each call used to consume the record BEFORE comparing it, so a replay that met a record of another type, or a schedule or workflow it did not ask for, lost the record that belonged to the next call and every later step read the history one place late (the cleat#4152 defect). They now consume nothing. `schedule_cron`'s divergence message is the dispatcher's shared identity text in place of its own, and it still compares all four arguments (workflow, expression, timezone, input). `delete_cron` still compares only the schedule id and still returns error code 1 with no message to the guest, because the host ABI gives it no output buffer. `list_crons` has no identity to compare. **`list_crons` is still never refused**, in a defer segment, after a refused event write and on shutdown, as before (`Refuse: neverRefuse`); the design's rule would refuse it, which would make it a host stop site every SDK has to check, and that decision is cleat#4239.
