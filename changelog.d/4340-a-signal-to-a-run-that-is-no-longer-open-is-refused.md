---
section: upgrade
---
- **A signal sent to a run that can never be reopened is now refused, where it used to be accepted and lost; a signal to a run that CAN be reopened is still accepted, but the reply no longer calls it delivered (cleat#4340).** A run that is `done` or `cancelled`, or that has continued as new, never reads another signal: the signal was stored under that run's own id and read by no one, and the sender was told `200 {"status":"delivered"}`. `POST /api/workflows/<id>/signal` now answers **`409 {"error":…, "detail":"workflow_not_open", "status":"done"|"cancelled", "continued_to":"<run>"}`** and stores nothing; `continued_to` is present only for a run that continued as new and names the **last run in its chain as of now**, which is the run to signal instead. The same refusal applies under an `Idempotency-Key`, and it does not spend the key. A run that does not exist or belongs to another tenant is still `404`. **What to do:** a caller that relied on `200` for one of those runs was having its signal dropped silently; treat `409` as "the run is over" and, if `continued_to` is present, signal that run. Inside a workflow, `SignalWorkflow` to such a target now returns the existing not-found outcome instead of success, and a plugin sees `plugin.ErrWorkflowNotFound` (so an event-trigger awaiter registered for the run is dropped, as for a missing one). **Unchanged, with one wording change:** a `failed`, `terminated` or `dead_lettered` run can be reopened under the same id (`retry`, `re-replay`) and would then read a signal stored before the redrive, so signals to those runs are still accepted and stored (the pattern "signal a dead-lettered run, then retry it" keeps working). The reply is the same `200`, but `status` is now `"stored"` instead of `"delivered"`, with `run_status` and a `detail` saying the run reads it only if it is retried or re-replayed; a client that compares `status` to `"delivered"` should handle `"stored"`. Whether those three should refuse instead (cleat#4345), and whether a signal to a continued run should be forwarded to its successor (cleat#4340), are left open.
