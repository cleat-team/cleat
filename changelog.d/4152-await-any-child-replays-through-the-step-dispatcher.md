- **`await_any_child` now replays through the step dispatcher; a replay that meets a record naming ANOTHER set of children is a divergence instead of being answered, and a guest drain that began before a suspension is no longer refused (cleat#4152, W3b).** The last of the three child awaits moved onto the dispatcher. **Two behaviour changes, each a named row in `the_child_await_move_tightens_only_these_test.go` that fails on the old code:** (1) an `await_any_child` record, answered or empty, whose child set is not this call's is now a replay divergence that consumes nothing; before, an answer recorded for another set was delivered to this call as its own, and another set's empty await was consumed and the call answered after it. A record that names no set is still this call's (the engine always records the set, so only a hand-built history lacks it). (2) the call's own "already suspended" guard is now the dispatcher's refusal, which answers the same word (`1 << 62`) but also lets through a guest's own defer drain that BEGAN BEFORE the suspension (cleat#3429), as `await_child` and `await_all_children` do since W3a; before, that await was refused. **Unchanged, and pinned by the existing table:** the child set is compared as a set in any order, the empties of one set followed by a record that is not its own still re-check the children fresh with that record left unread (so a call recorded after the empties runs again: cleat#4285, now a logged, named exemption), a resuming call still records no second empty row (cleat#3391), and the suspension word is still `1 << 62`.
