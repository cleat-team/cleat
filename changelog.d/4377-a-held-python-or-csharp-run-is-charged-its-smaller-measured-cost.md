section: upgrade
---
- **A held Python or C# run is now charged 4 MiB or 18 MiB against the resident-memory budget, not 17 or 66 (cleat#4377).** Those are the measured per-instance costs after cleat#4382 (Python, 12.1 to 1.3 MiB, 2.4 after a guest has churned 256 MiB of garbage) and cleat#4378 (C#, 48.7 to 16.7 MiB, the same after churn), plus 1 MiB for the store and session, rounded up. **At the same budget a worker therefore holds about four times as many Python runs and about 3.7 times as many C# runs.** The Go charge is unchanged at 24 MiB, and it is still an estimate by language, not a reading. **What is not in the figures is live data:** wasm memory never shrinks, so a guest that held 100 MiB once keeps it, one for one, and no per-language figure can know that; `--memory-soft-limit` is the backstop. **This is true only of a component built with those two changes:** a Python component built before cleat#4382 still costs 12.1 MiB per held run and a C# one built before cleat#4378 still costs 48.7, so each is charged about 8 or 31 MiB short, and the engine cannot tell the two builds apart from the bytes. **Rebuild your components;** `--memory-soft-limit`, which reads the cgroup's real use, is what catches one you have not. The default budget when `--resident-memory-percent` cannot be derived (the memory of the worker cannot be read) is 8 runs of the dearest language, which is now Go at 24 MiB, so 192 MiB.
