---
section: upgrade
---
- **A `call`, `call_with_retry`, `call_with_heartbeat`, `send` or `plugin_call` whose request differs from the one recorded now fails replay with a divergence; it used to be handed the recorded answer silently (cleat#4424).** A call is identified by its service and operation (a plugin call by its plugin and function) AND its request body (or input), compared as the exact string the history holds, the way `fetch` has always compared its body. Before, a call that asked the same service the same operation with a different body got the answer recorded for the old body, and the workflow went on as though nothing had changed. Now the replay stops, consuming nothing:

      replay divergence at step 3: call asked for something other than the call recorded there: call svc.op with a different request: [redacted: 38 bytes, sha256=7ae6...], recorded [redacted: 41 bytes, sha256=ed83...].
        actual request: [redacted: 38 bytes, sha256=7ae6...]
        expected request: [redacted: 41 bytes, sha256=ed83...]

  A body is named by its size and a short hash and never printed (cleat#4321). **Who this affects:** a workflow that builds a request from something that is not the same on replay (the wall clock, a random value, a generated id, an unsorted map), which `cleat vet` flags in many cases; `side_effect` or the durable clock gives such a value a recorded form. A run that diverges is finished by terminating it or resetting it, as for any divergence. **Histories written before this change:** no new field is recorded, so none is skipped and none needs a migration. The request and the input were already in every history, 0.5.0's compaction already kept them (read from the v0.5.0 source), and a plugin function that declares secret-only fields has always recorded a failed call's input with those fields masked, which the comparison accepts. An in-flight run therefore diverges after the upgrade only if its code now builds a different request than the one it recorded. **One limit:** a retried or heartbeat call records its request only on the call that ends the run (an attempt or heartbeat record carries none, and a policy refused for its length deliberately records none), so the body is checked there, and a history that stops inside a run is checked on service and operation alone, as before. The streaming plugin call (`plugin_call_streaming`) still compares plugin and function only.
