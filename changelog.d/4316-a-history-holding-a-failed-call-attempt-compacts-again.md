- **A history that holds a `call_attempt_failed` event (any call that retried) can be compacted again (cleat#4316).** Compaction had a code for that event type and no capture arm, so it refused the whole history, wrote no state and deleted nothing: such a run was never compacted and its history grew without bound, and, because the worker orders compaction candidates by history size and tries ten per store per tick, enough of them would have left no attempt for any other run. This was introduced after 0.5.0 (the event type and its code are not in the 0.5.0 tag), so it never shipped. The capture and expansion now carry the four fields the store persists for it (service, operation, attempt, error). A new test reads every `EventType` declared in `types.go` and requires each to be compactable or named as refused with a reason, so the next new event type cannot poison compaction the same way. **Not changed here:** a run whose compaction is refused for any reason is still retried every tick and still takes a candidate slot; a generic backoff is tracked separately.
