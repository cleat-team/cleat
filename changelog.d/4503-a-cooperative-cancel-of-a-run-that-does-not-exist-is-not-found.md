- **A cooperative cancel of a run that does not exist now answers 404 instead of 200 (cleat#4503).** `POST /api/workflows/{id}/cancel` without `"preemptive": true` stored its request with `UPDATE ... WHERE id = ?`, which matched nothing for an id no run has, and returned success, so a client was told `cancellation_requested` for a run that was not there. The signal, the terminate and the pre-emptive cancel already said `workflow not found` for the same id. With `--require-auth=true`, the default, the handler reads the run first and the store's answer was reachable only by a race with a delete; with `--require-auth=false` it was the whole answer. The PostgreSQL, MySQL and SQL Server stores now return `ErrWorkflowNotFound` when the run does not exist for the tenant, which is also what a run that belongs to another tenant reads as. A client that cancelled an id it had never started and relied on the 200 now gets a 404. Measured on PostgreSQL, MySQL and SQL Server against real stores, and through the HTTP handler against a stub store.
