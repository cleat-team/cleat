- **Behaviour change: the default `--wasm-memory-max-mb` is now 256 (it was 32), and the per-language C# memory floor is removed (cleat#4171, owner decision).** A worker with the flag unset now lets a guest's linear memory grow to 256 MiB instead of 32 MiB. It is a ceiling, not a reservation, so a small workflow pays nothing, but a workflow that was being stopped at 32 MiB now is not, and a worker running many workflows at once can in the worst case use `--concurrency` times this; size them together (`--memory-soft-limit` sees guest memory on cgroup v2 and on `/proc/meminfo`, where it is host-wide and also counts everything else on the machine; it is blind only on its last-resort Go-heap source, which macOS falls back to, cleat#4196). C# guests used to get 64 MiB when the flag was unset; the default now clears the 52 MiB a .NET guest needs to start, so the floor (`languageMemoryFloorBytes`) and the worker's practice of passing a limit only when the flag was set are gone, and `TestTheDefaultMemoryLimitClearsTheLargestRuntime` stops the default being lowered below that minimum. An operator who set `--wasm-memory-max-mb` is unaffected. `engine.DefaultMemoryLimitPages` is 4096 (was 512) for every user of the engine, which also moves the default of the wazero runtime that developer tooling runs on to 256 MiB: `cleat run` (embedded), `cleatctl replay` and `cleatctl debug`, `cleat-ts-run`, `cleat-bench` and `cleat/wasmtest` all call `engine.NewRuntime(ctx, 0, 0)`, which takes the default (`grep -rn 'NewRuntime(' --include='*.go' . | grep -v _test.go`). A library user building a wasmtime backend gets the same 256 MiB. Measured cost of a higher ceiling for a parked C# guest after allocation churn is in the residency design (section 9a, cleat#4195).
