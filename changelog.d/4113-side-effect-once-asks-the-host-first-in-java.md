- **Java: `HostCalls.sideEffectOnce(Supplier<String>)` asks the host first, so its function runs exactly once across the first run and every replay** (cleat#4113, part 5 of 6). `sideEffect(String)` takes a value computed before the host could be asked, so it cannot freeze anything; its javadoc says so and points at the new method (nothing is removed). A new name rather than an overload, because the stop-bit guard finds a method by name and checks the first declaration only. Verified through a really built TeaVM guest: the function ran once in the first run and 0 times in the replay. A second `@CleatEntry` in a fixture needs its generated export wrapper named from the fixture's main class, or TeaVM drops the export and the build says the entry is not exported. **UPGRADE NOTE: a Java module that calls `sideEffectOnce` imports `cleat_side_effect_recorded` and needs a worker that provides it, or it fails to link;** not measured: whether a module that never calls it still carries the import. Upgrade the workers before deploying such a module.
