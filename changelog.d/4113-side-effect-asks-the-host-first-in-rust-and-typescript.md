- **Rust and TypeScript: a side effect asks the host first, so its function runs exactly once across the first run and every replay** (cleat#4113, part 4 of 6; the TypeScript guest is the Rust `cleat-js-plugin` over the Rust SDK). Rust gains `HostCalls::side_effect_with(f)`, `side_effect_typed_with(f)` and the lookup `side_effect_recorded()`; the existing `side_effect(&str)` and `side_effect_typed(&T)` take an already computed value, so they cannot freeze anything, and their docs say so and name the new methods (nothing is removed). TypeScript's `ctx.sideEffect(compute)` keeps its signature and now asks first, synchronously, so the order of host calls in the history is unchanged. Verified through really built guests: the function ran once in the first run and 0 times in the replay, for both. `scripts/sdk-host-call-coverage-baseline.json`: Rust surface 73 to 76 methods, covered 58 to 59 (`side_effect_recorded` and `side_effect_typed_with` have no fixture call). **UPGRADE NOTE: a guest built with this SDK needs a worker that has this version's `cleat_side_effect_recorded` import, or it fails to link.** For Rust that is a module that calls `side_effect`, `side_effect_with` or `side_effect_typed_with`; **for TypeScript it is every workflow rebuilt with this plugin, including one that never calls `sideEffect`** (measured on `answer.ts`: the import count in the built module is 0 on develop and 1 here, because the plugin imports it unconditionally). Upgrade the workers before deploying rebuilt guests; guests already built are unaffected.
