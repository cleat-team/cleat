### 3.267 A core-ABI call's out-pointer result does not survive the component boundary, and three calls are in that state — 🔴 **OPEN** (WS-1, 2026-10-04)

**The state.** A core-ABI host call returns values through *out-pointers* into the guest's own
linear memory. Component dispatch writes into a **host** buffer, so the out-pointer does not survive
the crossing and the guest reads whatever sits at `OUTPUT_OFFSET`. A call in that shape has never
worked on a component.

**Three calls are in it, in two shapes**, and `engine/stop_correspondence_guard_test.go` already
carries a constant for each:

| call | WIT | on a component |
|---|---|---|
| `durable-await-signals` | declared, out-pointers (`python-sdk/wit/cleat.wit:163-170`, `-> u64`) | **bound** in Python, so a guest can call it and **reads a wrong value** |
| `cleat_start_detached` (cleat#1154) | no declaration | unbound — `pythonUnboundBaseline` and `sdkUnreachedBaseline` |
| `cleat_wait_for_event` (cleat#2998) | no declaration | unbound — the same two baselines |

The first is `reasonWitIsStillCoreABI` ("a world that declares the wrong thing"); the other two are
`reasonNotInTheComponentWorld` ("a world that declares nothing"). **The failure modes differ, and
aggregating them misdescribes one**: the two unbound calls cannot be made at all — nothing is
returned wrongly — while the bound one returns the wrong value today. That distinction is why the
two baselines above state the mode per call rather than in a sentence covering all three.

**WHY THIS ENTRY EXISTS IS THE HEADING, NOT THE PROSE.** The state *was* recorded — as a passage
inside §3.431's body. That section's heading is about the detached-run id it fixed and is marked
`✅ fixed`, so the plan's own scan is blind to the passage in **both** directions:
`scripts/check-plan-markers.py` reports headings carrying **no** status marker, so a live state
inside a heading that already has one is never reported; and a marker describes its own heading's
subject, so this passage cannot go *stale* in any way that scan can see. The state is live, and it
had no heading of its own to be found by.

**History worth keeping, because it cost four wrong citations.** Before 2026-10-04 the tree cited

**What would close this is not this entry.** It is `durable-wait-for-event` — and, for

`func(...) -> result<string, call-failure>`, a dispatcher in `component_cgo.go`, and regenerated
