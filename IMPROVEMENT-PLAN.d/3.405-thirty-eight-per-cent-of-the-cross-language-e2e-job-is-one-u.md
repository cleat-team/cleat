### 3.405 Thirty-eight per cent of the Cross-Language E2E job is one uncached install step — ✅ **FIXED 2026-11-15** (cleat#3925)

Found while costing §3.404, and recorded separately because it is not the harness's problem —
which is exactly why it would otherwise stay an aside in a message and never be fixed.

`Cross-Language WASM E2E` takes 364s. Of that, **166s is setup and 137s of the setup is a single
step**:

    gh api repos/:owner/:repo/actions/runs/33973787289/jobs \
      --jq '.jobs[] | .steps[] | "\(.name)\t\((.completed_at|fromdateiso8601)-(.started_at|fromdateiso8601))s"'

| step | s |
|---|---|
| toolchain setup (Go / Rust / Python / Node / Java / Gradle) | 27 |
| **Install Python WASM toolchain** — `pip install componentize-py` + `cargo install wasm-tools` | **137** |
| Install Python SDK | 2 |
| Run cross-language E2E tests | 169 |
| Run the cross-language suite | 24 |

`cargo install wasm-tools` builds from source on every run. Both pins are static, so this is
cacheable — by `actions/cache` on `~/.cargo/bin`, or by `taiki-e/install-action`, or by moving
both into the `cleat-py-toolchain` image the repo already ships and already uses for Python work
that cannot run on a Mac host.

**Why it is worth doing and worth doing separately.** 137s is very nearly what §3.404's entire
wave-1 harness costs (~145s for all five languages), and unlike the harness it buys nothing. It is also
the reason this job's cost has never been questioned: the number is large, it has been large
since the job was written, and nothing attributes it to a step.

**Resolved 2026-11-15 (cleat#3925).** Both halves of the entry, in one change: the install step is
pinned to a prebuilt `wasm-tools` tarball whose sha256 is checked offline, and the job is now a
four-leg matrix whose split is derived at run time from a single `E2E_SELECTOR`. Measured from the
runs' own step API, same units as the table above:

| step | before (run 43752676454) | after (run 43756490445, worst leg) |
|---|---|---|
| toolchain setup (Go / Rust / Python / Node / Java / Gradle) | 32 | 34 |
| **Install Python WASM toolchain** — `pip install componentize-py` + `cargo install wasm-tools` | **111** | **2** |
| Select this shard's tests (`go test -list`, compiles the test binary) | — | 25 |
| Install Python SDK | 2 | 3 |
| Run cross-language E2E tests | 527 | **199** |
| Run the cross-language suite (shard 1 only) | 14 | 28 |
| **job wall** | **698** | **265** |

The 111s was `cargo install wasm-tools` compiling from source on every run: it was 137s when this
entry was written and 111s on 2026-11-15, and it is 2s as a pinned tarball. Sharding is what took the
test step from 527s to 199s: the split is derived (`go test -list` + `(NR-1) % n` over a C-locale
sort) rather than four hand-written `-run` patterns, so no test can fall out of the union, and each
leg asserts both that it was assigned a non-empty slice and that every assigned test entered.

Two things this entry did not anticipate, both now measured rather than assumed:

- **Each leg pays the build in the select step** — `go test -list` runs the binary with `-test.list`,
  so it compiles: 22–25s per leg, and the run step then reuses it from the build cache. The
  199s figure above already includes that, and the 25s row is where it shows.
- **The critical path is 265s, not 698/4.** Shards land at 265 / 262 / 233 / 206s; shard 1 carries
  the 28s cross-language suite and shard 3 carries `TestPythonComponentExecutionFence` (94s on its
  own locally). A fifth leg would move the maximum to roughly 225s for another runner's setup, which
  is not worth it today.

The verification this entry demanded was followed: the shard split was exercised by extracting the
`run:` block from the parsed workflow YAML and running *that*, not a retyped approximation, and
`wasm-tools --version` on `PATH` is the step's own last line — the §3.403 gitleaks shape. Until now
nothing in this job's history had ever attributed its wall time to a step; the table above is the
first pair of runs where that is possible for both sides of the change.
